# 性能预算文档

## 1. 性能目标

### 基线性能
- **初始规划**: 0.3s ± 10% (标准场景)
- **最差情况**: < 2s (复杂场景)
- **内存峰值**: ≤ 512MB

### 增量重规划
- **平均时间**: ≤ 0.3s
- **成功率**: ≥ 50% 场景在0.3s内完成
- **加速比**: ≥ 2x (相比完整重规划)

## 3. 优化策略

### 算法优化
1. **启发式改进**
   - 使用A*的admissible heuristic
   - 动态调整启发权重
   - 目标导向的节点扩展

2. **搜索空间裁剪**
   - 早期终止条件
   - 分支限界
   - 双向搜索（可选）

3. **数据结构优化**
   - 使用最小堆优化开放列表
   - 空间哈希加速碰撞检测
   - 节点池复用

### 增量重规划优化
1. **局部修复**
   - 识别脏区域
   - 最小化重计算范围
   - 保留有效路径段

2. **缓存策略**
   - 节点缓存
   - 代价缓存
   - 路径段缓存

3. **自适应回退**
   - 动态判断是否需要完整重规划
   - 基于变更大小的策略选择
   - 性能监控与自动调整

## 4. 基准测试场景

### 场景1: 开放水域
- 障碍物: 5-10个
- 距离: 10km
- 预期时间: 0.1-0.2s

### 场景2: 港口区域
- 障碍物: 20-30个
- 距离: 5km
- 速度限制: 有
- 预期时间: 0.2-0.4s

### 场景3: 狭窄水道
- 障碍物: 30-50个
- 距离: 3km
- 约束: 严格
- 预期时间: 0.3-0.6s

### 场景4: TSS区域
- TSS约束: 有
- 距离: 15km
- 交通: 中等
- 预期时间: 0.2-0.3s

### 场景5: 极限测试
- 障碍物: 100+
- 距离: 20km
- 所有约束
- 预期时间: 1.0-2.0s

## 5. 性能监控

### 关键指标
```python
{
    "planning_time": float,      # 规划时间(秒)
    "nodes_expanded": int,        # 扩展节点数
    "nodes_visited": int,         # 访问节点数
    "memory_peak_mb": float,      # 峰值内存(MB)
    "path_length": float,         # 路径长度(米)
    "waypoint_count": int,        # 航点数量
    "replan_type": str,          # full/incremental
    "cache_hit_rate": float      # 缓存命中率
}
```

### 性能回归测试
1. 每次提交运行基准测试
2. 性能下降 > 10% 触发警告
3. 性能下降 > 20% 阻止合并

## 6. 配置建议

### 默认配置（平衡）
```python
PlannerConfig(
    grid_resolution=20.0,
    motion_step=20.0,
    max_iterations=5000,
    goal_tolerance_xy=20.0
)
```

### 快速配置（速度优先）
```python
PlannerConfig(
    grid_resolution=50.0,
    motion_step=50.0,
    max_iterations=2000,
    goal_tolerance_xy=50.0
)
```

### 精确配置（质量优先）
```python
PlannerConfig(
    grid_resolution=10.0,
    motion_step=10.0,
    max_iterations=10000,
    goal_tolerance_xy=10.0
)
```
